# 入院中の最終運用案

更新日: 2026-03-16

## 結論

今回は、以下の形で進めるのが一番自然です。

- 入院中の本線は `GitHub共有窓 + ブラウザ運用`
- `Sunshine / Moonlight` は完全に捨てず、条件が良い時だけ使う保険枠
- `外部WOL` は今回は採用しない
- `Android / ブラウザ案件` は次の別プロジェクトで進める

## 整理の理由

- 同一LANでの `Sunshine / Moonlight` 接続確認までは取れている
- ただし、病院の公共LANは不確実で、テザリング常用は通信量的に重い
- 一方で、`GitHub共有窓 + ブラウザ運用` なら、入院中でも現実的に回せる見込みがある
- `外部WOL` は技術的には前向きな条件が揃っているが、今回はそこまで仕上げなくても本線運用は成立する

## 今回の区切り方

今回の `COMMAND_CENTER` 側は、

- `入院前の止めどころ整理`
- `入院中はブラウザ中心運用を本線にする判断`

までで一旦締める。

## 親機側の前提

- `画面オフ` は可
- `本体スリープなし`

つまり、親機は切れないようにして置いていく前提。

## Sunshine / Moonlight を使うタイミング

本格使用するのは、

- `povo` や回線条件が整った時
- もしくは入院が長引いて、実機作業が必要になった時

に切る形で考える。

## 次の整理

`COMMAND_CENTER` 側はここで一旦区切って、
次は `Android / ブラウザ案件` を別プロジェクトで進める。

# リモート接続と外部WOLの判別メモ

更新日: 2026-03-16

## 結論

`Sunshine / Moonlight` の同一LAN接続は通っている。
`外部WOL` は、Windows 側とルーター側の前提条件はかなり揃っているが、まだ設定反映と実地テストはしていない。

今回の主案は、まず `画面オフ / 本体スリープなし` を本命にすること。
ただし最終判断として、`外部WOL` は今回は採用しない。
このメモは「前提はかなり揃っていたが、今回は保険候補として保留した」という判別記録として残す。

## 確認できた事実

- `Sunshine` は起動済み
- `https://localhost:47990` の Web UI に入れる
- `Moonlight` は同一LANでホスト検出、PINペアリング、`Desktop` 接続まで確認済み
- `scrcpy` は USB デバッグの再許可で再接続確認済み

## Windows 側のWOL前提

- 親機は有線LAN接続
- NIC は `Intel(R) Ethernet Connection (17) I219-V`
- `Wake on Magic Packet = Enabled`
- `wake_armed` に NIC が出ている

つまり、Windows 側だけ見れば `WOL` はかなり前向き。

## ルーター側の確認結果

- ルーターは `Huawei HG8045Q`
- 管理画面にはログイン可能
- WAN 側 IPv4 は `90.149.236.155`
- `AlwaysOn` 接続

つまり、`グローバルIPv4あり` で、外部からの経路は理屈上かなり前向き。

さらに、管理画面で以下の項目が見えている。

- `LAN > DHCPスタティックIP設定`
- `ネットワークアプリ > ARP設定`
- `転送ルール > ポートマッピング設定`
- `ネットワークアプリ > UPnP設定`

## まだ未確認の点

- BIOS / UEFI 側で `Wake-on-LAN` が有効か
- ルーターに固定IP / ARP / ポート設定を入れた時に実際に起きるか
- 病院Wi-Fi やスマホ回線からの実地起動確認

## 現実案

### A. 今回の本命

- `画面オフ`
- `本体スリープなし`

一番安定する。
病院から確実に入りたいならこの案が主案。

### B. 安全寄りの妥協案

- `本体スリープを 2〜3時間`
- 落ちたら家の人に起こしてもらう

外部WOLを組まなくても成立しやすい。

### C. 余力があれば試す案

- `DHCPスタティックIP設定`
- `ARP設定`
- `UDP のポートマッピング`

を入れて、外部WOLを実地テストする。

技術的には狙える構成に見えるが、今回はまだ未設定・未検証。

## 今回ここで止めた理由

- `同一LAN接続` まではすでに取れている
- 病院運用の本線は `ブラウザ中心` に寄せた方が現実的
- `外部WOL` は追加設定が入るわりに、今回の本線ではない
- 入院前の本命は、まず `画面オフ / スリープなし` と `GitHub共有窓 + ブラウザ運用` で十分成立する

## 今後の扱い

- 今回は採用しない
- ただし、将来あらためて `DHCP固定 / ARP / UDPポートマッピング / 実地テスト` をやれば、候補として再開できる
